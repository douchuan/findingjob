# 求职平台 — 产品规格文档 (Spec)

> 版本：v1.0-MVP  
> 日期：2026-07-31  
> 状态：ready-for-agent  
> 衍生自：`docs/PRD.md`，经 grilling 会话补充

---

## Problem Statement

传统求职网站以职位和公司为中心，求职者的技术能力被淹没在长篇简历中。对于开发者等技术岗位求职者，**代码能力比文字描述更能说明问题**，但现有平台没有有效展示。同时，求职市场和招聘市场都存在**信息不对称和信任缺失**——求职者不知道公司是否靠谱，HR 不知道候选人是否守约。

## Solution

构建一个**以技能为核心、双向评价体系为信任基础**的求职平台：

1. **技能标签系统**：求职者标注技能，HR 验证技能，搜索基于结构化技能标签
2. **代码能力展示（可选加分项）**：关联 GitHub/Gitee，展示高星项目
3. **职业规范性评价**：评价聚焦职业行为（是否守约、信息真实性），而非技能水平
4. **简历保护性开放**：简历默认不公开，HR 需申请，授权后 7 天有效
5. **企业严格认证**：营业执照 + 人工审核，确保 HR 身份真实

## User Stories

### 认证与注册

1. 作为求职者，我想用微信/支付宝/GitHub/Gitee 一键登录，所以我不需要记新密码
2. 作为求职者，我想用手机号 + 验证码登录，所以我在没有第三方账号时也能使用
3. 作为 HR，我想用企业邮箱注册并上传营业执照，所以我能通过企业认证获得完整权限
4. 作为管理员，我想审核 HR 提交的营业执照，所以我能确保平台上的企业身份真实
5. 作为用户，我想注销账号并设置 7 天冷静期，所以我有后悔的机会

### 求职者 - 个人信息

6. 作为求职者，我想填写姓名、头像、个人简介和期望职位，所以 HR 能快速了解我
7. 作为求职者，我想添加和管理我的技能标签（Java/React/K8s 等），所以 HR 能通过技能找到我
8. 作为求职者，我想为每个技能标注熟练度（了解/熟练/精通），所以 HR 能更准确地评估匹配度
9. 作为求职者，我想添加工作经历（公司/职位/时间段/描述，支持多条），所以我的经验背景更完整
10. 作为求职者，我想上传证书（名称/机构/时间/图片），所以我的资质有据可查
11. 作为求职者，我想关联 GitHub/Gitee（可选），所以我的代码项目能作为能力加分项展示
12. 作为求职者，我想上传 PDF 格式的简历（不超过 10MB），所以我有一份完整的能力档案
13. 作为求职者，我想查看哪些 HR 验证了我的技能，所以我的技能标签更有可信度

### 求职者 - 发现与互动

14. 作为求职者，我想浏览已入驻公司的列表和行业分布，所以我能找到可能感兴趣的公司
15. 作为求职者，我想查看某家公司收到的职业规范性评价统计，所以我能判断这家公司靠不靠谱
16. 作为求职者，我想标记某家公司我「感兴趣」，所以该公司的 HR 能收到通知并可能主动联系我
17. 作为求职者，我想查看 HR 对我发起的简历查看请求，所以我能决定是否授权
18. 作为求职者，我想对 HR 的职业规范性进行评价（守约/不规范等标签），所以我能帮助其他求职者避雷
19. 作为求职者，我想收到站内通知（简历请求、新评价、举报结果），所以我不会错过重要动态

### HR - 搜索与匹配

20. 作为 HR，我想按技能标签搜索求职者，所以我能找到具备所需技术的人
21. 作为 HR，我想按经验年限筛选搜索结果，所以我能找到资深度匹配的候选人
22. 作为 HR，我想按期望职位筛选，所以我能找到求职意向匹配的候选人
23. 作为 HR，我想看到求职者的技能标签、熟练度、已验证次数，所以我能快速判断匹配度
24. 作为 HR，我想查看求职者的公开信息（脱敏姓名、技能、经验概况、GitHub 项目），所以我不需要申请就能看到基本情况
25. 作为 HR，我想向求职者发起简历查看请求，所以我能获取完整简历和联系方式

### HR - 评价与管理

26. 作为 HR，我想在我通过简历请求后，对求职者的职业素养进行评价（守约/信息真实/面试爽约等标签），所以我能帮助其他 HR 识别靠谱候选人
27. 作为 HR，我想查看某家公司的评价统计，所以我能了解行业竞争情况
28. 作为 HR，我想管理我的企业信息（名称/行业/规模/描述/Logo），所以求职者能了解我们公司

### 管理员

29. 作为管理员，我想审核 HR 提交的企业营业执照，所以我能控制平台准入
30. 作为管理员，我想处理用户举报（恶意评价、违规内容），所以我能维护平台秩序
31. 作为管理员，我想封禁/解封用户，所以我能处理违规行为
32. 作为管理员，我想看到平台数据看板（注册数、交互数等），所以我能追踪 MVP 的成功指标

### 通用

33. 作为任何用户，我想对违规的评价或内容发起举报，所以我能维护平台环境
34. 作为任何用户，我想在我的账号注销 7 天后，我的个人信息被彻底删除，所以我的隐私得到保护
35. 作为任何用户，我想看到清晰的信息权限分层（公开/登录可见/授权可见），所以我知道什么信息对谁可见

## Implementation Decisions

### 1. 架构：7 个独立微服务

- **auth-service**（8001）：用户注册/登录、JWT 签发、OAuth（微信/支付宝/GitHub/Gitee）、手机号验证码
- **profile-service**（8002）：求职者档案、技能标签、工作经历、证书、GitHub/Gitee 项目数据
- **company-service**（8003）：公司信息、HR 信息、企业认证审核
- **rating-service**（8004）：双向评价、职业规范性标签、举报
- **resume-service**（8005）：简历上传、授权审批流、下载链接管理
- **storage-service**（8006）：统一文件存储（策略模式：Local/OSS/COS/S3）
- **notification-service**（8007）：站内通知、消息队列

角色互斥（MVP）：一个账号只能选择求职者或 HR 角色，不可同时拥有。

### 2. 搜索：PostgreSQL 全文搜索

- 使用 `tsvector`/`tsquery` 实现技能标签精确匹配 + 关键词搜索
- 不上 Elasticsearch（MVP 阶段）
- 排序策略：已验证技能数量 > 技能匹配度 > 经验年限 > 最近活跃时间

### 3. 技能标签系统

- 预置技能词库（`skill_tag` 表），支持自定义添加新标签
- 用户技能关联表（`user_skill`）：`user_id, skill_id, level (了解/熟练/精通), verified_count`
- HR 在查看过简历后可对求职者的具体技能进行验证，`verified_count + 1`
- 搜索时，`verified_count > 0` 的技能优先排序

### 4. 职业规范性评价系统

**求职者 → HR/公司：**
- 标签式评价：正面标签（「招聘规范」「承诺兑现」）/ 负面标签（「招聘不规范」「承诺未兑现」「面试不当」）
- 可选文字评论
- 需手机号验证通过即可投票
- 频率限制：每天最多 5 次评价

**HR → 求职者：**
- 标签式评价：正面标签（「守约」「信息真实」）/ 负面标签（「面试爽约」「信息不实」）
- **仅在与该求职者的简历请求通过后可评价**
- 可选文字评论
- 评价不可自行删除（防止刷好评删差评）

**举报机制：**
- 任何用户可举报评价（理由：恶意评价、侮辱性内容、不实信息）
- 管理员审核，确认违规则隐藏该评价
- 举报处理结果通知举报人

### 5. 信息权限分层

| 层级 | 条件 | 内容 |
|------|------|------|
| L1 - 公开 | 无需登录 | 脱敏姓名（张**）、头像、技能标签列表、工作年限、期望职位、GitHub 高星项目（可选） |
| L2 - 登录可见 | 已登录的认证 HR | 工作经历详情、证书列表、职业规范性评价 |
| L3 - 授权可见 | 简历请求通过的 HR | 完整简历 PDF、联系方式（电话/邮箱） |

### 6. 简历授权流程

1. HR 发起简历查看请求 → 生成 `resume_request` 记录（状态: pending）
2. 求职者收到站内通知，选择同意/拒绝
3. 同意 → 生成 7 天有效期的下载链接（预签名 URL）
4. 过期后链接失效，HR 需重新申请
5. 记录每次下载行为（用于技能验证权限判断）

### 7. 简历文件限制

- 仅支持 PDF 格式（MVP 阶段）
- 单文件不超过 10MB
- 浏览器在线预览 + 可选下载
- 文件存储使用 storage-service 的策略模式

### 8. 企业严格认证

- 注册时：企业名称 + 个人姓名 + 职位 + 联系方式
- 认证：上传营业执照照片
- 审核：管理员后台人工审核（MVP 阶段）
- 未认证：可浏览公司列表和求职者公开信息
- 已认证：可搜索、发起简历请求、评价
- 认证标识：HR 主页展示「已认证」

### 9. 通知系统

- 数据库表存储（`notification` 表），登录后拉取未读列表
- 轮询刷新（MVP 不做 WebSocket）
- 触发事件：
  - HR 发起简历请求 → 通知求职者
  - 求职者同意/拒绝 → 通知 HR
  - 简历授权到期 → 通知 HR
  - 收到职业规范性评价 → 通知被评价方
  - 举报被处理 → 通知举报人

### 10. 公司信息浏览（求职者端）

- 按行业/规模浏览已入驻公司列表
- 查看公司收到的评价统计（规范/不规范次数）
- 「感兴趣」按钮：点击后该公司 HR 收到通知

### 11. 数据删除与注销

- 注销冷静期：7 天，期间可撤销
- 注销后：个人信息、简历、技能标签、工作经历、证书全部删除
- 评价内容：匿名化保留（显示为「已注销用户」），维护评价体系完整性
- 已下载简历：不追溯删除

### 12. 前端多端策略

- 求职者/HR 端：React + Ant Design（响应式 + PWA）
- 管理员端：React + Ant Design Pro（同一项目，`/admin/*` 路由）
- 统一 JWT 认证，通过角色判断路由权限

### 13. API 设计

- RESTful，统一响应格式 `{ code, message, data }`
- 全局错误码枚举
- SpringDoc (Swagger UI) 自动生成文档
- 所有 API 通过 JWT 鉴权

### 14. 数据库

- PostgreSQL 15+，单实例，每个服务独立 Schema
- ORM：Spring Data JPA (Hibernate)

### 15. 核心数据模型

```
User (id, phone, name, avatar, created_at, role, status)
├── JobseekerProfile (user_id PK, years_of_experience, expected_position, github_token, gitee_token)
├── HRProfile (user_id PK, company_id, position, phone, verification_status)
├── WorkExperience (id, profile_id, company, position, start_date, end_date, description)
├── Certificate (id, profile_id, name, issuer, date, image_url)
├── UserSkill (user_id, skill_id, level, verified_count)
├── ResumeFile (id, user_id, file_key, file_size, uploaded_at)
├── Company (id, name, industry, size, description, logo, verification_status)
├── SkillTag (id, name, category, usage_count)
├── Rating (id, from_user_id, to_user_id, tags[], comment, created_at)
├── ResumeRequest (id, hr_id, jobseeker_id, status, download_url, expires_at)
├── Notification (id, user_id, type, content, is_read, created_at)
└── Report (id, reporter_id, target_type, target_id, reason, status)
```

### 16. 文件存储

- 策略模式接口：`FileStorageService { upload, download, delete, getUrl }`
- 实现：LocalFileStorage（默认）、AliyunOssStorage、TencentCosStorage、S3CompatibleStorage
- 配置切换：`storage.type: local | aliyun-oss | tencent-cos | s3`

### 17. 安全

- JWT 鉴权（所有 API）
- OAuth 登录，无密码存储
- API 限流：Ingress 层 + Resilience4j
- 文件上传校验：类型（仅 PDF）、大小（10MB）
- CORS：仅允许前端域名
- SQL 注入防护：JPA 参数化查询
- XSS 防护：前端输出编码

## Testing Decisions

### 测试原则

- **只测试外部行为，不测试实现细节**：测试 API 契约、业务规则、权限控制
- 优先集成测试（HTTP 端点 → 数据库），而非纯单元测试
- Mock 外部 OAuth 服务，使用测试用 JWT

### 测试范围

**auth-service：**
- OAuth 登录流程（Mock GitHub/Gitee OAuth）
- 手机号验证码登录（Mock 短信发送）
- JWT 签发与验证
- 角色权限路由（求职者不能访问 HR 端点，反之亦然）

**profile-service：**
- 技能标签 CRUD + 搜索（全文搜索）
- 工作经历/证书 CRUD
- GitHub/Gitee 项目数据拉取（Mock API）
- 技能验证：仅简历请求通过的 HR 可验证

**company-service：**
- 企业信息 CRUD
- HR 认证流程：提交营业执照 → 审核通过/拒绝
- 未认证 HR 权限限制

**rating-service：**
- 职业规范性评价：标签创建、展示、统计
- 评价权限：仅简历请求通过的 HR 可评价求职者
- 评价不可自行删除
- 举报流程：提交 → 审核 → 隐藏

**resume-service：**
- 简历上传（PDF 校验、10MB 限制）
- 授权流程：请求 → 同意/拒绝 → 生成链接 → 过期
- 链接过期后无法下载

**notification-service：**
- 通知创建、读取、标记已读
- 各触发事件正确生成通知

**权限与边界：**
- L1/L2/L3 信息权限分层：公开信息无需登录，L2 需认证 HR，L3 需简历请求通过
- 角色互斥：求职者不能访问 HR API
- 频率限制：评价每天最多 5 次

## Out of Scope

- **实时消息系统（WebSocket）**：MVP 用数据库 + 轮询
- **短信服务正式接入**：MVP 用模拟验证码
- **邮件通知**：v2.0+
- **高级搜索与筛选（多条件组合）**：MVP 仅支持技能/经验/期望职位筛选
- **数据看板/统计分析**：MVP 仅管理员基础看板
- **React Native 移动端 App**：v2.0+
- **国际化（i18n）**：v2.0+，MVP 仅中文
- **付费功能（会员、置顶等）**：v2.0+
- **Seata 分布式事务**：v2.0+
- **全链路监控（Zipkin）**：v2.0+
- **技能考试/认证体系**：不在 MVP 范围，用 HR 隐式验证替代
- **简历自动解析**：不在 MVP 范围，仅 PDF 存储和预览
- **职位发布功能**：MVP 是 HR 主动搜索模式，不发布职位
- **消息聊天系统**：MVP 不实现实时通信，仅站内通知

## Further Notes

### MVP 成功指标

| 指标 | 目标 |
|------|------|
| 活跃求职者注册数 | ≥ 100 |
| 认证企业/HR 数 | ≥ 10 |
| 简历请求次数 | ≥ 50 |

### 冷启动策略

- 前 7 天注册的用户不影响评价功能（无门槛，但频率限制）
- 管理员需要预先填充一部分技能词库
- GitHub/Gitee 是可选加分项，不强制绑定，服务新人

### 开发环境

- Docker Compose 开发环境
- K8s 生产部署配置
- Swagger UI 用于 API 调试
